# Skills

Skills are markdown playbooks (`SKILL.md`) that give an AI agent **operational guidance** for a
Godot Open MCP project — when to call which tool, in what order, and what to watch for. They ship
into your game project alongside the MCP client config so the agent always has the right playbook
on hand.

> **Skills vs. tools.** *Tools* (indexed in [MCP tools API](api/mcp-tools.md)) do things — they are
> the verbs the agent can call. *Skills* advise the agent on **how and when** to use those verbs.
> Runtime capabilities provide exact schemas; skills weave tools into reliable workflows.

## What ships

| Skill | Audience | When to read |
| ----- | -------- | ------------ |
| [`skills/godot-open-mcp/SKILL.md`](../skills/godot-open-mcp/SKILL.md) | Any agent driving a Godot 4.3+ (C# mono) project | Always — the core playbook |

Domain pack skills (`tilemap`, `navigation`, `particles`, `animation`, `csg`) are reserved for
future packs. Their tool-group ids appear in the catalog today with empty rosters; each pack will
ship its own focused playbook when it lands.

### Core playbook

`skills/godot-open-mcp/SKILL.md` is the playbook every agent reads first. It covers:

- **Preconditions** — what must be true before live tools work.
- **Non-negotiable rules** — discover first, scope every mutation, read the gate, no second editor.
- **Fast start** — the canonical `capabilities → manage_tools → ping → mutate` order.
- **Tool groups** — `core` is on by default; activate `typed-editor` for the typed surface.
- **Bridge triage** — what to do for each `bridge_status` token (`running` / `compiling` / `stopped`
  / `unreachable` / `dead_bridge`).
- **Gate workflow** — `paths_hint`, gate modes, the checkpoint → mutate → delta flow, and `apply_fix`
  preview / safe-fix / rollback semantics.
- **Routing** — `live` / `local` / `offline` / `live-first`, and the explicit "no batch route"
  limitation.
- **Key workflows** — safe mutate, dead-bridge recovery, reading with the editor closed.
- **Checklist** — before/after mutating.

The skill stays lean on purpose (~150 lines). Exhaustive schemas, rule catalogs, fix lists, and
gate JSON envelopes live in [MCP tools API](api/mcp-tools.md).

## How skills get installed

The skill is copied into your game project at the per-client path each MCP client expects. The
destination paths are defined once in [`skills/client-paths.json`](../skills/client-paths.json) —
the single source of truth consumed by every installer (the CLI `setup-mcp` command in later
phases, the Hub wizard, a future runtime skill generator). You do not edit this file by hand.

| MCP client | Skill destination |
| ---------- | ----------------- |
| Cursor | `.cursor/skills/godot-open-mcp/SKILL.md` |
| Claude (Desktop / Code) | `.claude/skills/godot-open-mcp/SKILL.md` |
| OpenCode | `.opencode/skills/godot-open-mcp/SKILL.md` |
| Generic `agents` clients (ZCode and similar) | `.agents/skills/godot-open-mcp/SKILL.md` |
| VS Code Copilot | `.vscode/skills/godot-open-mcp/SKILL.md` |
| Visual Studio Copilot | `.vs/skills/godot-open-mcp/SKILL.md` |
| Gemini | `.gemini/skills/godot-open-mcp/SKILL.md` |
| Cline | `.cline/skills/godot-open-mcp/SKILL.md` |
| Kilo Code | `.kilocode/skills/godot-open-mcp/SKILL.md` |

GitHub Copilot CLI has no project-local skill folder and maps to an empty target list. `custom`
maps to the four primary targets so a generic MCP client gets the skill everywhere it might be
read. The full MCP-client → skill-target mapping is in
[`skills/client-paths.json`](../skills/client-paths.json) (`mcpClientMapping`).

Until a setup command ships, copy the playbook manually: place
`skills/godot-open-mcp/SKILL.md` at the destination path for your client.

## Verification

Every change to the skill or to `client-paths.json` runs through `scripts/check-skill.mjs`, which:

- asserts the skill exists and is within the 130–180 line budget;
- resolves every backticked `godot_open_mcp_*` token in the skill against the MCP tool registry;
- rejects unprefixed tool ids, `batch` route claims, and unshipped `manage_tools` actions;
- validates `client-paths.json` against `client-paths.schema.json` (shape) and against the CLI
  `agentRegistry` (every MCP-client id and every mapping target is real);
- flags internal phase/spec references, forbidden reference-project names, and concrete
  secrets/home paths.

The audit is wired into CI; see [`skills/AGENTS.md`](../skills/AGENTS.md) for the ownership rules.
